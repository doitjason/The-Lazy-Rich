# Workflow: Write Column (지능형 칼럼 제작)

주제 발굴부터 중복 검토, 최종 검수, 배포까지 'The Lazy Rich' 칼럼 제작 과정을 정의한다.
모든 판정 기준은 `column_auditor` 스킬에 있다. 이 문서는 순서만 정한다.

> **Claude Code 에서 실행한다.** 중복 검사, 수치 재현, 분량 측정, 렌더 확인은
> 저장소와 실행 환경이 있어야 가능하다. 초안을 외부에서 받아 붙여 넣는 경우에도
> Step 4 이후는 반드시 여기서 수행한다.

## Step 1: 주제 선정 및 중복 검토
- **자율 발굴 시**: `src/content/columns` 전체를 분석해 중복되지 않는 주제 5개를
  유저에게 제안한다.
- **주제 제공 시**: 기존 칼럼과 겹치는지 검사하고, 유사하면 보완된 관점을 제시해
  승인을 받는다.
- 주제뿐 아니라 **사용할 사례와 비유까지** 기존 글과 겹치지 않는지 본다.
  (스킬 [A] 의 소진된 사례 목록 참조)

## Step 2: 기초 설계
- 3줄 요약, 소제목 위계, CTA 배치를 먼저 잡는다.
- 이 단계에서 **분량 계획**을 세운다. 2,000자를 어떤 내용으로 채울지 정하지 않으면
  나중에 수식어로 늘리게 된다. 스킬 [B] 의 네 가지(반례 / 한계 / 한국 조건 / 출처)를
  어디에 넣을지 미리 배치한다.

## Step 3: 사실 확보
- 인용할 통계·발언·법령의 근거를 **먼저** 확보한다. 글을 쓰고 나서 출처를 찾으면
  없는 근거를 그럴듯하게 맞추게 된다.
- 확인되지 않으면 그 문장을 쓰지 않는다. 세법 수치는 법령 원문으로 확인한다.
- 웹 검색이 필요하면 이 단계에서 끝낸다.

## Step 4: 콘텐츠 제작
- 스킬 [C] 문체, [G] 윤문 규칙을 적용해 작성한다.
- 본문 볼드체(`**`) 금지.
- **본문에 면책 조항 블록을 넣지 않는다.** 페이지 컴포넌트가 자동으로 렌더한다.
  넣으면 한 페이지에 두 번 출력된다.

## Step 5: 스마트 링크 및 수치 검증
- 독자의 실행 욕구가 정점인 지점에 계산기 딥링크나 AI 멘토 링크를 단독 문단으로 넣는다.
- **수치는 계산으로 검증한다.** `src/lib/finance-utils.ts` 의 계산 함수로 딥링크
  파라미터를 그대로 넣어 돌려 보고 본문 숫자와 대조한다.
- 딥링크에 `inflation` 을 빠뜨리면 기본값 3 이 적용된다. 파라미터를 전부 명시한다.
- 본문·3줄 요약·결론의 같은 수치가 서로 일치하는지 확인한다.

## Step 6: 데이터 등록
- `src/data/columns.ts` 의 `COLUMNS` 배열 최상단에 객체를 추가한다.
- `id`, `title`, `subtitle`, `category`, `categoryLabel`, `categoryColor`,
  `categoryBg`, `thumbnailEmoji`, `author`, `publishedAt`, `readTime`, `tags`,
  `featured`, `relatedBookIds` 를 채운다.
- **`updatedAt` 은 넣지 않는다.** 신규 발행 글은 개정된 적이 없다.
- `id` 는 파일명(`src/content/columns/<id>.mdx`)과 일치해야 한다.

## Step 7: 자동 검사
- `npm run check:content` — 분량 하한과 도서 구조 문제를 잡는다.
- `npm run build` — MDX 파싱, 타입 오류를 잡는다.
- 둘 중 하나라도 실패하면 다음 단계로 넘어가지 않는다.

## Step 8: 렌더 확인 (건너뛰지 않는다)
- dev 서버를 띄워 새 칼럼 페이지를 연다.
- 확인 항목: 3줄 요약 카드 정상 렌더 / 소제목이 `h2`·`h3` 로 출력 / 짧은 문장이
  제목으로 잘못 승격되지 않음 / 광고 슬롯 3개 / **면책 조항이 한 번만** 출력.
- 소스 검사만으로는 위 항목 중 어느 것도 보증되지 않는다. 실제로 이 단계를 건너뛰어
  면책 조항 중복이 배포된 적이 있다.

## Step 9: 최종 오딧 및 보고
- `column_auditor` 의 [발행 전 체크리스트]를 전수 확인한다.
- 유저에게 보고할 때 항목별 결과를 밝힌다. 통과하지 못한 항목이 있으면
  무엇이 왜 남았는지 함께 적는다. 통과했다고 뭉뚱그리지 않는다.
