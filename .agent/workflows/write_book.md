# Workflow: Write Book (추천도서 소개글)

`src/data/books.ts` 의 도서 항목을 추가하거나 소개글을 고치는 절차.
판정 기준은 `content_auditor` 스킬에 있다. 이 문서는 순서와 **칼럼과 다른 부분**만 정한다.

> **칼럼 워크플로우와 갈리는 지점**
> - 계산기 딥링크와 수치 검증이 **없다** (Step 5 해당 없음)
> - MDX 파일이 아니라 **TS 파일 안의 JSON 문자열**을 편집한다
> - 쿠팡 제휴 링크와 표지 이미지가 필요하다 — **일부는 유저만 발급할 수 있다**
> - 렌더러 휴리스틱이 칼럼과 다르다 (40자 기준, 제목 연속 함정)

## Step 0: 이 책을 추가할 것인가

- 이미 있는 21권과 **성격이 겹치는지** 본다. 같은 저자, 같은 주제의 책이 이미 있으면
  둘 다 얕아진다. (예: 번스타인 2권은 서로 다른 층위를 다루므로 공존이 정당하다)
- 도서 페이지는 **전부 쿠팡 제휴 링크를 달고 있다.** 책을 늘리면 사이트 전체에서
  제휴 페이지 비중이 올라간다. 2026-03 반려 사유가 "가치가 별로 없는 콘텐츠"였고
  이 구조가 그 판정에 유리하지 않다.
  → **비제휴 콘텐츠(칼럼)가 함께 늘고 있는지** 확인하고 판단한다.

## Step 1: 책 내용 파악

- 그 책이 **실제로 무엇을 주장하는지** 확인한다. 목차, 서문, 신뢰할 수 있는 서평.
- **읽은 척하지 않는다.** 1인칭 독서 경험을 지어내지 않는다. 에디터는 금융업
  종사자가 아닌 개인 투자자로 공개되어 있고, 소개글이 그와 어긋나면 감점이다.
  (스킬 [F] 저자 정체성)
- 확인 못 한 내용은 쓰지 않는다. 출간 연도, 개정판 유무, 번역본 판본은 확인 가능한
  사실이므로 확인해서 쓴다.

## Step 2: 구성 설계

- **진입 각도를 기존 21권과 다르게 잡는다.** 저자 이력 / 특정 개념 / 반론 / 유명한
  일화 / 오해 바로잡기 등. 도입-전개-마무리 3단을 모든 책에 적용하지 않는다.
- 본문 1,200자를 무엇으로 채울지 먼저 정한다. 나중에 수식어로 늘리게 되는 것을 막는다.
- **반드시 배치할 두 섹션** (스킬 [I])
  1. **한계와 안 맞는 독자** — 낡은 부분, 원서 연도와 개정판, 저자의 이후 예측이
     빗나간 이력, 어떤 독자에게는 맞지 않는 이유
  2. **한국 독자 조건** — 국내 상장 상품으로 대체 가능한지, 계좌별 과세 차이,
     번역본 판본 확인
- 가능하면 **비제휴 경로**를 한 문단 넣는다. 원문 무료 공개(버크셔 주주서한,
  오크트리 메모), 도서관 등. 책을 안 사도 되는 길을 알려 주는 문단이 제휴 페이지가
  아니라는 신호다.

## Step 3: 작성

- `3줄 요약` 으로 시작한다. 항목은 `\n\n` 으로 나눈다. (칼럼은 연속된 줄, 도서는 빈 줄)
- 본문 블록도 `\n\n` 으로 나눈다.
- **제휴 고지를 본문에 쓰지 않는다.** 페이지 상단과 전역 푸터가 처리한다.
- 렌더러 함정 (`references/rendering.md`)
  - **40자 미만 + 마침표 없는** 블록은 `h4` 제목이 된다. 짧은 문단은 마침표로 끝낸다.
  - **제목 블록이 연달아 두 개** 오면 본문 없는 제목이 화면에 노출된다.
  - 불릿(`- `)은 **한 블록 안에서 단일 개행**으로 잇는다.

## Step 4: 파일 편집 — 직접 고치지 말 것

`longDescription` 은 JSON 스타일 문자열이라 `\n` 이스케이프가 들어 있다. 에디터로
직접 고치면 이스케이프가 깨지기 쉽다.

- **스크립트로 파싱해 교체한다.** id 로 항목을 찾아 문자열 전체를 갈아끼우는 방식.
- 블록을 중간에 삽입할 때는 **기준 블록의 텍스트로 위치를 지정**한다. "뒤에서 N번째"
  방식은 개수를 잘못 세기 쉽고, 실제로 그 실수로 제목이 연달아 붙은 적이 있다.

## Step 5: 데이터 등록 (신규 도서만)

`RECOMMENDED_BOOKS` 배열에 객체를 추가한다.

| 필드 | 비고 |
|---|---|
| `id` | URL 이 된다 (`/books/<id>`). 영문 케밥케이스 |
| `title`, `author` | 번역본 기준. 저자는 원어 병기 |
| `tag`, `tagColor`, `bgLight` | 기존 항목의 색 조합을 참고해 중복을 피한다 |
| `description` | 목록 카드용 2~3문장. 여기도 상투어 금지 |
| `longDescription` | 본문. 1,200자 하한 |
| `imgUrl` | 표지. `naverQuery` 로 자동 조회되지만 실패하면 이 값이 쓰인다 |
| `link` | **쿠팡 파트너스 링크 — 유저만 발급 가능** |
| `naverQuery` | ISBN 또는 검색어 |
| `level` | `beginner` / `intermediate` / `advanced` |

**유저에게 요청해야 하는 것**: 쿠팡 파트너스 링크. 없이는 등록을 완료할 수 없으므로
Step 0 에서 미리 확보한다.

## Step 6: 검사

```bash
npm run check:books     # 분량 하한 + 제목 블록 연속
npm run build           # 타입 오류
```

`check:books` 는 제목이 연달아 붙은 경우를 잡아 준다. 눈으로 찾기 어려운 항목이다.

## Step 7: 렌더 확인 (건너뛰지 않는다)

```bash
npm run dev
```

`/books/<id>` 를 열고 확인한다.

- [ ] 3줄 요약 카드 정상 렌더
- [ ] 소제목이 `h4` 로 출력되고, **본문 없는 제목이 없다**
- [ ] 불릿이 목록으로 렌더 (각 줄이 제목이 되지 않았다)
- [ ] 표지 이미지 로드
- [ ] 쿠팡 고지가 상단에 한 번
- [ ] 하단 구매 버튼 동작

모바일 폭에서도 본다.

## Step 8: 보고

`content_auditor` 의 [발행 전 체크리스트] 중 도서에 해당하는 항목을 확인한다.
수치 검증 항목은 해당 없음으로 처리하고, 그 사실을 밝힌다.
