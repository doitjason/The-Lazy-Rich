# Skill: Column Auditor

'The Lazy Rich' 의 칼럼(`src/content/columns/*.mdx`)과 도서 소개글
(`src/data/books.ts`)을 검증하고 교정한다.

**Claude Code 에서 실행한다.** 중복 검사, 수치 재현, 분량 측정, 렌더 확인은 저장소와
실행 환경이 있어야 가능하다. 외부에서 받은 초안도 아래 절차는 여기서 거친다.

**대전제**: 금융 콘텐츠는 YMYL 이다. 구글 스팸 정책이 겨냥하는 것은 AI 작성 여부가
아니라 "독자적 가치 없이 대량 생산된 콘텐츠"다. 이 사이트는 2026-03 에 "가치가 별로
없는 콘텐츠" 사유로 애드센스 반려를 받았고, 아래 규칙은 그 대응이다.
→ 근거와 사고 이력: `references/incidents.md`

---

## 1. 자동 검사 — 먼저 돌린다

```bash
npm run check:content   # 분량 + 도서 구조 + 문체
npm run build           # MDX 파싱, 타입
```

기계가 잡아 주므로 **아래 항목은 외울 필요 없다.** 걸리면 그때 고친다.

| 검사 | 기준 |
|---|---|
| 칼럼 분량 | 2,000자 (권장 2,300~2,500) |
| 도서 분량 | 1,200자 (권장 1,400+) |
| 도서 구조 | 제목 블록 연속 금지 |
| 본문 볼드체 | 금지 (헤딩 예외) |
| 상투어 | `든든한 길잡이/나침반/조력자`, `부드럽게 조언`, `일깨워줍니다` 등 |
| 양비론 마무리 | 마지막 문단의 `정답은 없`, `균형이 중요`, `본인에게 맞는` 등 |
| 종결어미 연속 · 전환어 밀도 · 문단 길이 · 소진된 비유 · 섹션 균일성 | [주의] 보고 |

분량 측정은 3줄 요약과 링크·헤딩·공백을 제외한 순수 글자 수다.
**미달이면 발행하지 않는다.** 심사관은 무작위 표본을 열어 본다.

## 2. 사람이 판단할 것

기계가 못 잡는 항목. 여기가 이 스킬의 본체다.

### [F] 출처 및 신뢰성 — 최우선

*   통계·발언·법령을 인용하면 **근거를 본문에 밝힌다.** 출처 없는 단정이 YMYL 최대
    감점 요인이다.
*   확인되지 않는 수치는 **삭제하거나** 완화형으로 바꾼다. 그럴듯하게 남겨 두는 것이
    가장 위험하다. (전례: RIA 칼럼 전체 삭제)
*   법령은 **개정안과 시행법을 구분**한다. 시행일과 법률 번호를 확인하고 그 기준을
    본문에 밝힌다.
*   "전문가들은", "성공한 투자자들은 하나같이" 같은 주체 불명의 권위 인용 금지.
*   **저자는 금융업에 종사하지 않는 개인 투자자다.** (`/about`, `EDITOR_BIO` 에 공개)
    자격·경력을 암시하지 않고, **읽은 척·겪은 척하는 1인칭 일화를 지어내지 않는다.**
    비전문가임을 밝히고 근거를 대는 구조는 불리하지 않다. 없는 전문성을 주장하는
    쪽이 훨씬 위험하다.

### [A] 중복

*   작성 전 `src/content/columns` 전체를 검색한다. 주제·결론이 70% 이상 겹치면 중단.
*   **사례와 비유까지** 본다. 개별 글은 멀쩡해도 모아 놓으면 템플릿으로 읽힌다.
    소진된 사례 목록: `references/incidents.md`

### [J] 읽을 가치

1~2 는 감점을 피하는 기준이다. 전부 통과해도 읽을 이유가 없는 글이 나올 수 있다.
승인은 목표가 아니라 전제다.

*   **한 편에 질문 하나.** 한 문장으로 못 쓰면 주제가 두 개다.
*   **첫 세 문장**에 계속 읽을 이유가 있어야 한다. 독자는 3줄 요약을 이미 읽고 왔다.
*   **반박 가능한 주장을 하나는 남긴다.** 아무도 반대하지 않을 주장은 읽을 가치가 없다.
    단 근거 없는 단정과는 다르다. [F] 가 우선한다.
*   이미 아는 것을 다시 설명하지 않는다. 복리가 뭔지 매번 쓰지 않는다. 링크한다.
*   **장면을 넣는다.** "2008년 금융위기"보다 "코스피가 하루 10% 넘게 빠지던 2008년
    10월". 단 지어내지 않는다.
*   **행동으로 끝낸다.** "생각해 보십시오"는 행동이 아니다.
*   **남는 문장 하나.** 없으면 정보를 전달했을 뿐 읽힌 것이 아니다.

### [G] AI Slop — 구조 지표

표층(종결어미·상투어)은 스크립트가 잡는다. 여기는 구조다.

*   **대칭 구조 금지.** 모든 논점에 반론을 같은 분량으로 붙이지 않는다. 사람 글은
    한쪽으로 기울어 있다. 중요한 곳에 지면을 더 쓰고 덜 중요한 것은 한 문장으로.
*   **리스트 도피 금지.** 설명하기 어려운 것을 불릿으로 흩어 놓지 않는다. 불릿은
    진짜 병렬 항목에만.
*   **주제문 반복 구조 금지.** 모든 문단을 "~는 중요합니다"로 시작하지 않는다.
*   **정보 밀도 불균등화.** 전체가 같은 밀도면 어디를 봐야 할지 알 수 없다.
*   **범용 독자 금지.** 누가 어떤 상황에서 이 글을 검색했는지 한 문장으로 적을 수
    있어야 한다.

### [B] 분량을 채우는 방법

같은 말을 풀어 쓰거나 수식어를 붙이는 것을 **금지**한다. 분량만 늘고 평가는 내려간다.
아래 넷으로 늘린다. 분량과 E-E-A-T 가 함께 올라간다.

*   **반례**: 주장이 통하지 않았던 실제 사례. (올웨더에 2022년 주식·채권 동반 하락)
*   **한계 명시**: 어떤 조건에서만 성립하는지. 파는 쪽이 잘 쓰지 않는 문단이라
    신뢰 신호로 가장 강하다.
*   **한국 조건**: 금융소득종합과세, 연금저축·IRP·ISA 과세 차이, 환율, 건강보험료,
    전세, DSR.
*   **출처 구체화**: 모호한 인용을 실제 연구·발언·공시로.

## 3. 형식 규칙 — 어기면 화면이 깨진다

*   **`3줄 요약` 은 UI 파싱 키워드다.** 요약 카드 렌더와 광고 분할이 이 문자열에
    걸려 있다. 표현을 바꾸거나 지우지 않는다. 칼럼은 항목을 연속된 줄로, 도서는
    `\n\n` 으로 나눈다.
*   **소제목은 `##`/`###` 로 명시한다.** 4~6개. 렌더러의 제목 승격 휴리스틱에
    의존하지 않는다.
*   **면책 조항을 본문에 쓰지 않는다.** 페이지 컴포넌트가 모든 칼럼에 자동 렌더한다.
    넣으면 한 페이지에 두 번 출력된다. (전례 있음)
    세제·제도의 개별 주의 문구는 본문에 넣어도 된다. 그건 서술의 일부다.
*   **제휴 고지도 본문에 쓰지 않는다.** 도서 페이지 상단과 전역 푸터가 처리한다.
*   **수치는 A=B.** 본문 값은 계산기 딥링크 파라미터로 나오는 값과 일치해야 한다.
    *   `inflation` 을 빠뜨리면 **기본값 3 이 적용**된다. 파라미터를 전부 명시한다.
    *   `src/lib/finance-utils.ts` 로 실제 계산해 대조한다. 눈으로 넘기지 않는다.
    *   수치를 고치면 **본문·3줄 요약·결론**을 함께 고친다.
    *   멘토 링크는 `/mentor?mentor=...` 형식. 구형 `/?mentor=` 는 신규 사용 금지.
*   **날짜**: `publishedAt` 은 고정. 본문을 실질적으로 고쳤을 때만 `updatedAt` 을
    적는다. 오래돼 보인다고 날짜를 조정하는 것은 금지. 발행 주기를 맞추려고 분량
    미달 글을 올리는 것도 금지.
*   **문단은 3~4문장.** 이 사이트는 `max-w-md` 단일 컬럼이다. 광고가 본문을
    3등분하므로 **각 구간이 독립적으로 읽을 만해야** 한다.

→ 렌더러 동작 상세: `references/rendering.md`

## [I] 도서 소개글 추가 규칙

도서 페이지는 **전부 쿠팡 제휴 링크를 달고 있다.** 본문이 얇으면 thin affiliate 로
분류된다.

*   **구조를 책마다 다르게.** 도입-전개-마무리 3단을 모든 책에 적용하지 않는다.
    저자 이력에서, 개념에서, 반론에서 — 진입 각도를 바꾼다.
*   **반드시 담을 두 가지** (제휴 페이지가 안 쓰는 내용이라 신뢰 신호로 가장 강하다)
    1.  **한계와 안 맞는 독자**: 낡은 부분, 원서 출간 연도와 개정판, 저자의 이후
        예측이 빗나간 이력 등
    2.  **한국 독자 조건**: 국내 상장 상품 대체 가능성, 계좌별 과세 차이, 번역본 판본
*   **비제휴 경로가 있으면 알린다.** 원문 무료 공개(버크셔 주주서한, 오크트리 메모 등).
    책을 안 사도 되는 길을 알려 주는 문단이 제휴 페이지가 아니라는 신호다.

## 4. 실행 순서

1.  **중복 검사** — [A]. 주제뿐 아니라 사례·비유까지.
2.  **사실 확보** — [F]. 출처를 **먼저** 잡는다. 쓰고 나서 찾으면 없는 근거를
    그럴듯하게 맞추게 된다.
3.  **작성** — 2·3 절 적용.
4.  **수치 검증** — 계산으로 확인한다.
5.  **자동 검사** — `npm run check:content && npm run build`.
6.  **렌더 확인** — dev 서버에서 실제 화면. 건너뛰지 않는다.
    소스 검사로는 보증되지 않는다. (전례 있음)
7.  **보고** — 통과하지 못한 항목이 있으면 무엇이 왜 남았는지 함께 밝힌다.

## 5. 발행 전 체크리스트

**판단 항목** (기계가 못 잡는다)

- [ ] 이 글이 답하는 질문을 한 문장으로 쓸 수 있다
- [ ] 첫 세 문장에 계속 읽을 이유가 있다
- [ ] 누군가는 동의하지 않을 주장이 하나 있고, 근거를 갖췄다
- [ ] 마지막이 독자가 할 수 있는 행동으로 끝난다
- [ ] 옮겨 적고 싶은 문장이 하나 있다
- [ ] 모든 통계·발언·법령에 확인 가능한 근거가 붙어 있다
- [ ] 확인 못 한 수치는 쓰지 않았다
- [ ] 자격·경력·1인칭 경험을 지어내지 않았다
- [ ] 기존 34편과 주제·사례·비유가 겹치지 않는다
- [ ] 섹션 길이가 전부 비슷하지 않다
- [ ] 본문에 면책 조항을 넣지 않았다
- [ ] 계산기 딥링크 수치 = 본문 = 3줄 요약
